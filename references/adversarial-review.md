# 按风险触发的对抗性审查

目标是找到会改变处置决定的反证，同时检查方案是否超出需求。默认一轮聚焦审查；修正后只复核相关发现，不循环增加审查角色。

## 输入与执行

给审查者当前目标、范围与授权、原始现象和关键证据、候选方案、必要验收。把候选方案标为待审假设，不提供预设通过结论。验证根因时保留观察顺序，避免把事后结论当作当时已知事实。

在宿主支持且允许委派时，高影响或用户明确要求独立审查的任务可使用一名独立只读审查者。审查者不得改文件、运行有副作用的实验或扩大检查范围。否则由主代理进行反例自查，并明确它不是独立审查；不假装多角色思考等同于独立证据。

## 只检查与本次决定相关的反问

1. 根因：还有哪种机制同样解释现象？什么最小证据可区分？
2. 持久性：重新启动、重试或正常环境变化是否暴露临时依赖？仅选择相关条件。
3. 主线：若不实施此改进，当前目标具体在哪里失败？可否删减方案？
4. 验证：测试是否能发现原机制，是否绕过了关键边界？哪些额外测试不会改变判断？
5. 权限与结论：是否超范围，或将恢复、假设、记录提升为已解决事实？

每个有效发现包含证据、影响、最小修正或最小区分实验。推测标为假设；没有具体反例时不捏造发现。

结论为通过、针对发现修正、或证据不足。新发现依实际影响重新分级；只有相关重大风险才阻断当前目标。若反例已被必要证据排除，停止，不为取得形式上的一致继续审查。
